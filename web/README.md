# Pi Arm 网页控制台

网页控制台用于查看机械臂状态、设置运动目标、记录点位和运行重复定位测试。服务启动后，在浏览器打开 `http://192.168.2.110:8000/control.html`。控制器地址默认填入 `ws://192.168.2.110:8765`，可直接点击“连接”，也可先修改地址。整体安装、启动、端口和 CAN 配置见 [根 README](../README.md)。

## 界面与连接

左侧导航包含“机械臂示教”“在线编程”“点位管理”和“运行记录”。顶部显示连接、使能状态和当前运行，停止按钮随页面滚动保持可见。切换“开发者”视图可打开诊断和方向测试。

示教页左侧操作，右侧查看模型与当前反馈：

- **步进示教**：选择关节、基坐标位置或姿态，填写步长，点击对应轴的加减按钮。每次点击执行一次增量，受理后等待终态，再允许下一次运动。
- **目标运动**：选择单关节、六关节、末端位姿或输出轴，编辑目标和速度，再预览、执行。“整组目标与预设姿态”中保留整组运动、零位和打包姿态。
- **拖拽示教**：进入或结束实机拖拽。三维模型的鼠标拖动设置在模型下方“模型交互与预览设置”中。

点位管理页将点库与录入表并排显示，可按名称、备注和类型筛选；A/B 重复测试在页面底部展开。运行记录页选择记录后，在旁边查看本次步骤、结果和停止确认，或导出 JSON/CSV。

连接后核对后端类型（`real` 实机、`mock` 模拟）、运行模式（正常、只读或 `commissioning` 维护）、标定 ID、六轴反馈新鲜度和控制许可。正常控制模式下，手动使能后即可设置并执行运动。FAULT 或标定无效时，可在诊断区查看原始数据和原因。灰色模型显示离线参考或最后有效姿态；状态超过 1.5 s 未更新时，界面关闭新运动入口。

顶部“停止运动”请求取消当前轨迹并保持当前位置，适用于关节、输出轴、预设姿态、笛卡尔运动和循环到点等待。已下使能或处于拖拽示教时，保持原有释放状态。出现 `HOLD UNCONFIRMED` 时，查看诊断并处理通信或电机故障后重试停止。

程序或脚本占用机械臂时，工作台显示名称、步骤与状态；其他客户端不能插入运动。暂停会在当前运动步骤到位后生效，等待步骤立即暂停计时；继续前重新检查运行条件。停止结束本次运行，不能用继续恢复。网页关闭后，树莓派上已经启动的程序和单次运动仍会执行；需要中止时先点击停止并核对结果。

## 坐标、反馈与速度

- J1–J6 是主动关节相对转角，顺序为 joint_01、joint_02、joint_04、joint_05、joint_06、joint_09。
- “输出轴”指减速器输出端相对模型零位的角，已包含标定偏移；腕部 CAN4 → J5、CAN5 → J4。
- XYZ 表示 tool0 法兰中心在 base_link 中的位置，单位 mm；RX/RY/RZ 分别为滚转、俯仰、偏航角（RPY），单位 °，采用固定轴旋转 `Rz(yaw) Ry(pitch) Rx(roll)`。
- “各关节坐标系相对 base_link 的位姿”显示 URDF 子坐标系的 XYZ/RPY。pitch 接近 ±90° 时，RPY 存在奇异性。
- 关节反馈由编码器数据经绳索模型反解得到；三维模型和坐标显示使用同一帧反馈做正运动学（FK）计算。

角速度默认 **5°/s**、最高 **10°/s**。普通目标运动同时受关节/姿态速度和“目标运动 → 输出轴限速”约束，修改对下一次任务生效。

回零/打包的关节速度在“预设姿态”区域调整；重复测试使用其面板内单独的速度快照。绳索耦合会使输出轴比关节走得更远：打包到零位时第 3 输出轴约走 449.2°，输出轴限速 5°/s 需要约 90 s，整臂按耗时最长的轴同步运动。

点位与常用位置数据显示最多三位小数，ROS/CAN 和磁盘原始存档保持内部精度。

## 运动与预览

“运动到打包姿态”使用后端显示的打包目标。“运动到零位”将六个关节移到 0°。在机械零位采集软件零点的操作见[方向测试](#方向测试)。

| 操作 | 输入与行为 |
| --- | --- |
| 单关节 / 多关节 | 通过 DirectMove 执行单关节或完整关节目标；未选关节的目标保持起点角度，耦合电机仍可能一起转动 |
| 输出轴目标 | 六个模型输出角，先绳索反解，再检查关节/输出限位与执行 |
| 笛卡尔控制 | 输入 base 下 tool0 的 XYZ/RPY，使用 Pilz LIN 规划末端直线运动 |
| 有限步进 | 选择关节、基坐标位置或基坐标旋转轴与步长；后端从新鲜静止反馈生成一次目标并校验 |
| 打包 / 零位 | 打包姿态是机械零位，J1 至 J6 为 `[0, 100.7, -85.6, 0, 0, 0]°`。零位的六个关节角均为 0° |
| 输出轴反解 / 关节路径 | 返回关节目标，并显示与 DirectMove 相同的关节线性插值路径 |
| 笛卡尔 IK | 逆运动学：用当前反馈作种子求目标位姿的关节解，并检查端点碰撞 |
| LIN 路径规划 | 末端直线路径预览，与实际 MoveL 使用相同规划管线 |

先用预览查看目标和路径，再点击对应按钮执行。后端会从最新反馈重新生成轨迹并检查执行条件。DirectMove、输出轴和预设姿态采用关节插值，使用前确认沿途空间；需要末端直线运动时选择笛卡尔控制。

J2/J3 起点和反馈可用 3° 容差，目标使用标准限位；容差带内的起点先过渡到最近标准边界。任务完成时，后端已核验每轴误差、静止和连续稳定，默认到位容差为 0.2°、稳定时间为 0.5 s。

### 三维模型与拖动

模型 X 红/Y 绿/Z 蓝，Z 向上、内部采用米制；正视相机位于基座 −Y 侧，侧视位于 +X，俯视位于 +Z。模型按实际解算角显示，超出标准限位时给出提示。

关节滑块和模型拖动用于设置目标预览。展开“模型交互与预览设置”，选择连杆/J1–J6，将鼠标操作切为“拖动关节”，左右拖动即可改变所选关节角度。

开启“松手执行”后，每个完整手势至多提交一个单关节绝对目标，沿用速度和正常运动门禁。Esc、失焦、后台、切换视图、停止或反馈失效会取消手势；重新连接不保留勾选。开始重复测试会关闭松手执行。

青绿色模型显示目标，橙线显示 tool0 路径。动画回放压缩至约 10 秒，实际运动时间参考界面中的“估计轨迹时长”。编辑目标/速度、起点变化、开始运动或状态过期时，需重新生成预览。

IK/LIN 预览在正常控制模式下提供；只读和 commissioning 模式显示反馈姿态。若模型加载失败，可继续使用数值诊断和停止按钮，并检查浏览器 WebGL 支持及模型资源。

## 到位保持与实机拖拽示教

正常运动到位后，电机持续保持最终位置。需要手动搬动并记录姿态时：

1. 等待任务结束、反馈连续静止，支撑机械臂后点击“进入拖拽示教”。系统通过 0x81 释放位置闭环，并暂停普通运动入口。
2. 支撑并移动机械臂，静止后可在点位面板保存当前反馈。
3. 点击“结束示教并保持当前位置”。后端采集当前协议角，以 1°/s 输出轴速度上限建立位置保持，并核验回包和反馈。

示教释放状态持续到操作者结束示教。若反馈超出允许范围，先在支撑状态下移回有效范围；退出失败时按界面原因处理后重试。

## 点位示教与备份

点位类型为六关节（°）或笛卡尔（mm/°）。来源：

1. **手动输入**：选择类型、六个数值、名称和备注后保存。
2. **当前实机反馈**：静止且标定/运动学有效时，由服务端采集同帧反馈；允许未使能或只读时录入。
3. **模型预览目标**：关闭松手执行，拖动或计算预览后保存完整六关节目标。

选择点位并点击“加载到运动表单”，核对目标和预览后点击运动。加载时检查硬件类型、模型和关节顺序，标定变化时提示重新核验；实际执行时检查限位及规划条件。

点位保存在树莓派，默认 `~/.local/share/pi_arm/points-real.json` / `points-mock.json`，跨刷新/服务重启保留。可通过启动参数 `points_file` 更改。最多 500 个、2 MiB，名称唯一；库版本冲突时刷新后重试，损坏文件保留原内容并报错。

点位记录携带稳定 ID、revision、来源、时间、单位/坐标系、模型哈希和参考信息；反馈来源额外保留原始电机协议角与 ROS 时间。支持搜索、详情、修改、删除确认和无损 JSON 导出。名称及备注修改保留身份与来源，数值修改标记为手动录入。导入先预检，默认追加且跳过冲突，也可选择更新相同 ID，确认后整批提交。首次修改既有点库前保留 `.v0.5.bak`。

## 步骤程序

打开“在线编程”，从顶部打开程序或新建。左侧指令栏添加关节直接运动、MoveJ、MoveL、等待或有限循环；中间选择步骤，右侧编辑参数、上移、下移或删除。运动步骤可手动填写六个目标值，也可引用已保存点位。选择有限循环后，可添加循环内步骤；循环支持一层。

底部提供校验和启动，顶部保存及导入导出。校验遇到无效数值时定位到对应步骤并保留输入。运行中高亮当前位置，同时显示本次固定快照；编辑影响下一次启动。运行结束后在运行记录中查阅结果。

启动时固定步骤、点位值和参数；运行中的编辑影响下一次启动。网页关闭、刷新或断线不影响树莓派执行，重连查看同一次运行。服务或控制器重启后旧运行标记为中断，不自动续跑。运行记录提供参数快照、步骤结果、错误和停止确认，可导出 JSON/CSV。参数和接口见 [执行服务](../docs/execution.md)，脚本用法见 [Python SDK](../sdk/python/README.md)。

## 重复定位测试

入口为“点位示教 → 重复定位测试”。选择已保存的起始点 A 与目标点 B，两点必须同类型、不同目标，且与当前硬件、模型、标定、坐标系/关节顺序一致。

1. 设置循环次数（1–1000，默认 10）、每次到点等待（0–3600 s，默认 3）。
2. 设置关节/姿态速度及输出轴上限（默认 5°/s、最高 10°/s）；笛卡尔点另有直线速度，默认 5 mm/s。
3. 点击“开始循环运动”。每轮 **A → 到位等待 → B → 到位等待并记录**，初始到 A 包含在第一轮内。完成最后一轮停在 B 保持。
4. “停止测试与运动”取消后续循环并请求保持当前位置。记录持久保存在树莓派，可随时导出 JSON/CSV。

匹配任务成功、`arrival_state=reached` 且六电机反馈新鲜静止后，开始到点等待计时。完整一轮包含两段运动、两次等待和反馈延迟。开始测试时保存本组目标和参数快照，运行期间按这组设置执行。

后端结合角度变化和持续速度判定运动，停止后约需 0.3～0.8 s 确认反馈稳定。等待期间重新检测到运动会中止测试。到位核验和测量等待分别计时，判定方法见 [硬件包说明](../src/pi_arm_hardware/README.md#反馈运动状态)。

关节点走 DirectMove，笛卡尔点走 LIN；本面板线加速度固定 10 mm/s²，姿态加速度请求值 10°/s²，实际依现有 Pilz 处理。无解、超限、任务取消/失败、反馈过期、失能等情况结束运行，不自动重试。运动由后端超时约束，到点等待单独计时。

测试由树莓派独立执行，网页进入后台、关闭、刷新或断线后继续。重连可查看当前 A/B 运行，旧测试可在运行记录中查询。

### 五轮试跑与循环周期

点击“试跑 5 轮并测周期”，使用当前选中的 A/B 点位、速度和等待参数执行 5 轮，结束后在 B 保持。试跑和普通循环都统计周期，普通循环次数由独立输入框设置。

- **本轮耗时**：本轮发起前往 A 的请求，到 B 等待结束并记录的时间。第一轮包含任意初始位置到 A 的就位过程，单独标注。
- **目标点记录间隔**：前一次 B 记录到本次 B 记录，包括 B→A、A 等待、A→B、B 等待、到位核验和通信调度耗时。五轮产生四个完整间隔，用于计算平均、最短、最长和极差。
- 表格显示最近 10 轮，JSON/CSV 保留全部已完成记录。中止的半轮不进入统计；新测试重新计时。
- 周期用树莓派单调时钟计时，单位秒，显示三位小数。到位时刻取自执行服务核对成功终态的时间，记录日期为 UTC。
- 导出 schema v2 包含 `timing` 统计和每行 `cycle_duration_s`、`target_interval_s`、`arrival_interval_s`、`target_arrived_at`、`target_arrived_elapsed_s`、`captured_elapsed_s`。首条间隔为 JSON `null` / CSV 空单元格；UTC 时间用于与外部记录对照。

### 与激光跟踪仪配合测稳定点

现场使用中图 GTS3800 和 SpatialMaster 记录外部测量，网页负责 A/B 运动与反馈记录。两套记录按采样点和时间对应整理。

1. 根据现场软件提供的功能设置稳定点采样，核对静止触发、离开后重新触发及数据保存方式。
2. 根据靶球静置噪声设置稳定阈值；网页到点等待应覆盖末端稳定、跟踪仪判定和采样所需时间。
3. 用五轮试跑检查每次 B 停留的采样情况。A/B 两处都有记录时，按空间位置区分；漏采时保留记录并检查停留时间、遮挡和触发设置。

网页周期统计用于估计测试节拍，跟踪仪采样按其实际稳定点判定进行。

### 测试记录含义

每轮在 B 等待结束时记录同帧关节反馈、base 下 tool0 XYZ/RPY、原始协议角、目标角、任务号、UTC 时间、容差与到位状态。

- `verification_error_joint_angles_deg`：后端最后一次到位核验保存的目标−反馈误差。
- `sampled_error_joint_angles_deg`：等待结束时用目标减去当前反馈，单独反映采样时误差。
- JSON 包含 A/B 快照、速度/等待/次数、标定/模型编号、结果及中止原因；可以中途导出当前快照。
- A/B CSV 每行一个目标点样本，用轮次/时间对照外部量具；运行记录 CSV 每行一个执行步骤。

记录持久保存在树莓派的 real/mock 独立数据库。评估实际末端精度时，将这些记录与外部测量按采样点对应分析。

## 故障恢复与诊断

切换“开发者”视图并打开“开发诊断”，在“电机故障恢复”中选择 CAN1–6。清错（0x9B）检查所选电机的新鲜、静止反馈，其他电机暂时失联时仍可操作；存在活动任务、已知运动或未确认停止时需先处理。重启所选电机（0x07）要求六轴反馈有效、整臂静止，并先支撑机械臂。标定无效时，这些操作仍依据原始电机反馈判断。

CAN 收发报错后，驱动会自动重新连接并恢复轮询；故障前的运动任务需要重新发起。若显示“停止未确认”，通信恢复后先点击停止并检查结果。持续欠压、过热或接线问题仍需排除实际故障。

重启结果通过后续反馈核验：反馈恢复、无错且电机处于关闭状态时报告成功。输出轴参考变化超过 0.2° 或核验失败时，显示 `REBOOT_REFERENCE_UNVERIFIED`，按提示核对姿态和参考。ROM 标零后的操作见 [人工重新上电流程](../src/pi_arm_hardware/config/README.md)。

开发诊断可导出原始协议角、原始/模型输出角、软件偏移、关节角及错误/标定信息，供排查零偏、方向、几何和机械回差。

## 方向测试

停止正常服务后运行 `bash scripts/start_web.sh --commissioning`。将实物放到打包姿态并保持静止，在“开发者 → 方向测试”中核对参考角，勾选姿态确认，点击“采集并保存软件零点”。成功后页面显示采集结果，下次启动自动加载该接口的零点文件。其他已知姿态可用[命令行采集](../src/pi_arm_tasks/pi_arm_tasks/zero_reference/README.md)。

方向测试由 `--commissioning` 服务提供。电机测试的正负按钮按协议方向解释，步长对应输出轴角幅度，单步最大 5°、距首次测试起点 ±30°。关节测试单步最大 0.5°，按绳索映射带动耦合电机，并检查输出轴行程。

测试角速度默认 5°/s、上限 10°/s；速度低于协议分辨率时，界面会提示调整。浏览器持续发送测试心跳，超时后停止测试。操作时记录命令、协议角变化、实物方向和模型方向，再导出观察数据。

| `model/` | 构建/启动时从源 URDF 导出的显示资源 |

页面通过项目自带的 HTTP 服务加载静态文件和本地 Three.js 0.180.0 / URDF Loader 0.12.6。首次模型资源约 15 MiB，浏览器需支持 WebGL2 和 DecompressionStream。

控制、点位、循环脚本及样式使用相同发布版本的 `?v=`。修改互相依赖的资源时，一并更新 HTML 版本参数。若更新后点位卡片正常而下拉框为空，可刷新列表或重新打开页面，加载同一版本的资源。

前端测试使用离线 WebSocket 拦截或独立 mock 服务，入口及依赖见 [scripts/README.md](../scripts/README.md)。
