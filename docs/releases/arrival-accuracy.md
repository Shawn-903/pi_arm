# 到位判定修复 · 2026-09-17

之前控制器的六轴 `goal` 位置容差均为 0，ROS JTC 将其解释为不检查位置误差。
manager 仅凭控制器成功、停止应答和静止反馈结束任务，因此静止但偏离目标 0–2° 也可能显示成功。

现在每条轨迹显式配置每轴位置容差，默认 0.2°；控制器最多等待 10 s 收敛。
manager 随后独立确认所有轴位置、速度、反馈新鲜度，连续 0.5 s 到位后才撤销运动许可。
停止应答完成后再核验一次，停止导致的漂移也会报告 `GOAL_NOT_REACHED`。
网页显示目标、末次核验误差和判定阶段，不通过修改显示值或重新置零掩盖误差。

配置位于 `src/pi_arm_bringup/config/manager.yaml`，与 `controllers.yaml` 的默认容差保持一致。
修改配置需重新构建并重启服务。当前开发在独立 `/tmp` install 中验证，尚未切换正在运行的实机。

## 验证

- 独立构建 10 个包成功；colcon 共 182 项测试通过。
- `scripts/test_arrival_integration.py`：真实 manager + 合成反馈，验证提前成功但残差 1°、稳定收敛、停止后漂移三个场景。
- `scripts/test_web_mock.py`：单轴、整臂、输出轴、停止、规划失败、断线反馈通过。
- 测试不连接物理 CAN，不发送实机运动。

这修复了成功判定漏洞，不能证明机械定位误差已经消失。现场切换后以 1°/s 回零，记录六轴目标/反馈/误差与停止前后变化。
若未到位，保留报错数据再分析伺服跟随、停止行为、绳索弹性和模型标定；不要简单放大容差使其通过。
反馈关节角由电机和绳索模型推算，物理关节的精度仍需独立测量。
