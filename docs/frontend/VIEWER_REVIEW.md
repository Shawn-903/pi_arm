# 三维机械臂视图：软件验收与现场确认

日期：2026-09-17。分支：`feature/web-console-v2`。控制基线：`v0.1.0-stage1`。
状态：软件实现与 mock 验证完成，实机姿态和方向对应关系待操作者确认。
本轮未启动实机服务、未发真实 CAN 运动，也未执行实机笛卡尔运动。

## 交付内容

- 三维工作台和方向测试页共享同一模型；旋转/平移/缩放、三维/正视/侧视/俯视、居中、坐标轴和网格。
- 使用现有 `joint_names` + `current_joint_angles`，按名称映射并从度转弧度；读取现有新鲜度、运动学状态和错误。
- 显示 J1–J6 角度；点击连杆或轴按钮高亮关节及其随动连杆，可定位原有单关节控制面板。
- base_link/tool0 坐标轴和模型末端位置；模型保持 ROS 的 Z 向上、米制坐标，文字位置显示毫米。
- 反馈超过标准指令限位时保留解算值并标黄；设备/解算故障标红，缺失/重复关节名、非有限角、失效或陈旧反馈不更新模型。
- 初次未连接显示“离线零位参考”；断线/无效反馈保留并标灰最后有效姿态，隐藏实时角度和末端数值。
- 半透明青绿色叠加关节目标或零位/打包姿态；预览不修改控制输入、不下发运动。
  单关节面板预览表示该面板的**六轴目标集合**，不是某个“运动”按钮的单轴命令。
  打包目标来自当前后端标定；目标超限或输入不完整时隐藏预览。
- 模型资源缺失、浏览器不支持 WebGL2 或图形上下文丢失时给出提示，原有数值和控制链继续工作。

未实现输出轴目标反解预览、笛卡尔 IK 预览、规划路径显示、碰撞可执行性验证、拖动模型控制实机。
当前只预览关节姿态，不能用模型自洽证明绳索标定或实机精度正确。

## 模型与资源来源

`src/pi_arm_description/urdf/pi_arm.urdf.xacro` 是唯一模型来源。
`scripts/export_web_model.py` 在构建和网页启动时自动展开 Xacro，保留 joint origin/axis/limit/mimic 和 visual origin，
移除与显示无关的控制、惯性和碰撞描述，输出到忽略提交的 `web/model/`。
源文件、导出 URDF 和每个网格的 SHA-256 写入清单；网格 URL 含内容摘要，避免使用旧网格缓存。
没有另设电机方向、零偏或绳索转换；这些由既有后端统一处理。

独立关节顺序：`joint_01, joint_02, joint_04, joint_05, joint_06, joint_09`。
随动关系：`joint_03=joint_04`，`joint_07=joint_06`，`joint_08=-joint_05`。
URDF Loader 默认的关节裁剪已关闭，反馈容差不会被可视化偷偷裁剪；预览目标单独检查标准限位。

10 个原始 STL 共 43,660,440 字节，经无损 gzip 后为 15,544,252 字节，873,192 个三角面保持不变。
没有改变 CAD 几何或 ROS 碰撞模型；显示原模型并保留真实装配特征。
使用按需渲染、最多 1.5 倍像素比；离开视口/隐藏页面时暂停绘制。尚无低面数 LOD，也未实测手机 GPU 帧率。
三维依赖本地固定为 Three.js 0.180.0 / URDF Loader 0.12.6；普通启动不需要 npm 或外网。
依赖源码地址、许可证和可复现构建方法见 `web/vendor/README.md`。

## 软件验证

- 导出 URDF 的全部关节定义与源文件一致；10 个压缩网格解压后与原始文件逐字节一致。
- 独立 Python 矩阵正解对比浏览器 11 个 link：零位、打包、六轴各 ±5°、20 组随机姿态，共 34 组。
  逐矩阵元素误差阈值 `2e-12`，包括三个 mimic 关节、安装旋转和 tool0 固定偏移。
- 打乱反馈关节顺序仍能正确显示；缺失/重复名称、缺少角度、状态不可用、单轴陈旧、反解错误保持最后姿态。
- J2=102.7°、J3=-87.6° 不被显示裁剪，超限高亮；电机故障高亮。
- 目标预览与反馈模型隔离：修改预览不会改变反馈姿态；随动关节、空输入、目标超限及打包来源/断线限制通过。
- 视角、选择关节、定位控制面板、预览、页面导航测试累计发送 **0 条机械臂请求**。
- 1440×1100、1024×768、390×844 布局无页面水平溢出，工作台/方向测试切换通过。
- 模型 404、WebGL 初始化失败、运行中图形上下文丢失降级检查；连接控件保持可用。
- 完整 ROS mock 链对比网页 tool0 与后端 TF：位置和旋转矩阵阈值 `1e-6`，此项只读、不发送运动。
- 原有 `test_web_console.py`、`test_web_diagnostics.py`、`test_web_mock.py` 通过；覆盖关节/输出轴目标、停止、请求拒绝、诊断和陈旧门禁。
- JavaScript/Python/Bash 语法与 `git diff --check` 通过。未修改 ROS 核心控制代码，因此未重复全量 C++/vcan 测试。

结束 mock 时再次观察到系统 MoveIt `move_group` 的析构段错误（阶段一已记录）。该退出问题尚未修复；

## 待现场确认

第一步只比对当前姿态，无须使能或运动。没有其他 CAN 服务运行时启动：

```bash
cd /home/cr/pi_arm
bash scripts/start_web.sh --monitor can_interface:=can0 \
  calibration_file:=/home/cr/pi_arm/src/pi_arm_hardware/config/pack_reference_calibration.R06.recorded.yaml
```

打开 `http://树莓派IP:8000/control.html`，点击“连接”。三维区应显示“模型反馈”和“实机模型”。
若仍为“离线零位参考”或“最后有效姿态”，先看界面给出的原因及开发诊断，不把该图当作当前姿态。

1. 保持当前姿态，从正视、侧视观察模型和机械臂的肩、肘、腕、法兰是否对应。机械臂若处于打包姿态，再选择“打包姿态”叠加对照；仅查看，不执行。
2. 确认模型底座朝向与现场选定的基坐标一致；正视摄像机位于基座 -Y 侧，侧视位于 +X 侧，俯视位于 +Z 侧。旋转视角不会改变坐标定义。
3. 确认 tool0 原点确实是法兰中心、没有工具偏置；观察 X 红/Y 绿/Z 蓝轴和预期安装方向。
4. 静态比对通过后，Ctrl+C 退出只读服务，再由操作者按既有 commissioning 流程逐轴点动。
   使用开发者“方向测试”页的三维视图，记录“电机/关节编号、正负命令、实物运动方向、模型运动方向”。
   单轴电机运动可能通过绳索耦合影响多个关节，这是要观察的物理关系，不应强制只转一个模型关节。
5. 如不一致，导出诊断并保留现场照片/观察记录，以区分模型安装坐标、绳索方向、零偏和弹性误差。

现场确认前保持现有 R06 标定、限位及速度配置；本轮不重新置零、不改变机械方向。
