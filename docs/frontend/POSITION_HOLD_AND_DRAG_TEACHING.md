# 到位保持、拖拽示教与点位精度

正常的六关节、输出轴目标、预设姿态、MoveJ/MoveL 运动在反馈满足位置和速度容差后，关闭本次轨迹的写入许可，保留电机最后的 A4 位置闭环。正常完成不再发送 0x81；异常、超时、取消和“停止运动”仍执行原有停止链。停止不等同于保持，不应用停止按钮代替示教结束。

网页“总体控制”中提供“进入拖拽示教”。操作者先支撑机械臂，再确认退出所有电机的位置闭环（0x81，保留运行状态与角度参考）；这不是重力补偿或力控拖动。只有在无活动任务、反馈新鲜且连续静止时才允许切换。示教期间禁止普通运动和直接使能；多个浏览器通过后端状态看到同一个示教状态，断开网页不会自动重新上力。

拖动结束并静止后，可以在点位库记录当前反馈。点击“结束示教并保持当前位置”，后端重新检查标定、运动学、CAN 反馈和电机错误，捕获各电机当前协议角，并以 1°/s 输出轴速度上限发送 A4 保持这些位置。不会使用 0x88 恢复旧目标。收到 A4 回包并确认新鲜、已使能且静止的位置反馈后才报告成功。失败时保留示教禁止运动状态，并尝试停止；应查看电机反馈确认实际状态。

若拖动到反馈容差范围以外，需要先在支撑状态下移回有效范围，才能结束示教。正常关节目标仍使用标准限位，本修改不放宽限位、不改零点、不改标定。

WebSocket 的点位、关节角、末端 XYZ/RPY、点位库和预览目标以最多三位小数输出；界面输入中的输出轴角在弧度转度后取三位小数。内部 ROS/CAN 控制、点位磁盘存档、弧度诊断、四元数和时间戳保留原精度。JSON 数值不强制保留末尾零，点位卡片仍显示三位小数。

关键实现：

- `src/pi_arm_interfaces/srv/SetTeaching.srv`：后端示教切换。
- `src/pi_arm_interfaces/srv/SetMotionArmed.srv`：成功到位时的 `hold_position` 释放方式。
- `src/pi_arm_manager/src/manager_node.cpp`：到位验证及互斥入口。
- `src/pi_arm_hardware/src/backend.cpp`：保持、示教状态和旧轨迹隔离。
- `src/pi_arm_can/src/can_driver.cpp`：当前位置 A4 保持与回包确认。
- `src/pi_arm_websocket/pi_arm_websocket/protocol.py`：仅输出阶段的点位精度处理。

回归入口：`scripts/test_motion_safety_vcan.py`（固定 vcan0）、`scripts/test_web_drag_teaching.py`（离线拦截 WebSocket）、各包单元测试。实机的持位力矩、停止位置闭环后的支撑和结束示教仍需现场确认。

协议依据：仓库 `docs/CAN总线通讯协议V2.6.pdf` 第 8 页，0x80 会清除转动圈数，0x81 停止不清除运行状态。因此示教切换不使用 0x80，也不自动发送 0x88。电机仍显示使能不代表处于位置保持，应同时查看示教状态；若另行关闭电机，需要核验角度参考后再恢复控制。

软件验证（2026-09-17）：完整构建通过；235 项单元测试通过；26 组生产 RealBackend 虚拟 CAN 场景通过，包括无位移目标保持、保持期间旧控制命令隔离、显式停止、示教后锁定新位置、反馈超时和 A4 回包缺失。离线网页按钮测试及 mock 整臂的关节/输出轴/笛卡尔运动和示教后再次运动通过。未对实机执行运动或示教切换。
