# 网页重复定位测试

入口：点位示教 → 重复定位测试。静态网页改动，无需编译或重启服务；刷新页面后加载。
若已保存点位有内容但下拉框为空，属于旧点位脚本未同步新面板的缓存问题。页面已为相互依赖脚本加版本参数，重新打开更新后的页面即可加载一致版本，原点位不受影响。

## 操作

1. 在点位库保存起始点 A、目标点 B。可手动录入、记录静止反馈或保存模型目标。
2. 如果使用实机拖拽示教，先结束示教并保持，再使系统进入正常可运动状态。
3. 选择 A/B。两个点必须同类型、不同目标，且硬件类型、模型、标定编号、坐标系和关节顺序与当前服务一致。更换标定后旧点需重新核验并录入。
4. 设置次数（1–1000，默认 10）、每次到点等待（0–3600 秒，默认 3）、关节/姿态速度及输出轴限速（默认 5°/s、最高 10°/s）。笛卡尔点另外设置直线速度，默认 5 mm/s。
5. 点击「开始循环运动」。先到 A，确认到位/静止后等待，然后到 B，确认到位/静止后等待并记录，计为一轮。重复 N 轮，最后在 B 保持。初始到 A 的运动包含在第一轮内。
6. 测试结束或中止后导出 JSON / CSV，再开始下一组或刷新页面。记录保存在当前页面内存，新测试会替换上一组记录。

**间隔定义**：每次到点后的等待时间，不是请求发送间隔或固定周期。整轮耗时 = 两段实际运动时间 + 两次等待 + 通信/状态刷新延迟；等待计时以浏览器单调时钟为准，不承诺实时精度。

速度使用测试面板自己的参数，开始时冻结整组点位与参数；工作台速度框不影响已开始的测试。即使关节速度为 10°/s，输出轴上限为 5°/s 时仍会按绳索耦合延长轨迹。正常运动链的限位和到位核验继续生效。

六关节点位使用 `move` / DirectMove 关节插值，不保证末端直线，也不经过 MoveIt 避障。笛卡尔点位使用 `movel` / 现有 LIN 链，坐标为 base_link 下 tool0，无解、限位或规划失败即中止；线加速度固定 10 mm/s²，姿态加速度请求字段为 10°/s²（沿用后端 Pilz 加速度处理规则）。

## 运行与中止

- 每段只提交一个任务，必须收到返回 task_id 对应的成功状态、`arrival_state=reached` 及六电机新鲜静止反馈，才进入到点等待。请求接受不算到位，旧任务成功不算本次成功。
- 测试期间锁定参数、关闭模型松手执行，并禁止本页其他运动插入。其他客户端任务编号改变时中止本循环；当前系统不提供跨客户端独占控制锁，测试应只使用一个控制页面。
- 「停止测试与运动」和全局停止均结束循环；前者发送现有 `stop_motion`。任务失败/取消、反馈过期、失去使能、进入示教、标定/模型变化也中止，并尝试软件停止。
- 页面转入后台、刷新或关闭会取消后续循环并尝试停止；重新连接不会恢复任务。**连接中断或页面被强制关闭时，停止请求不保证送达，当前单段运动可能继续至目标并保持**。后端没有新增循环或断线看门狗，不能依赖浏览器作为物理急停。
- 单段任务等待最多 30 分钟，超过即中止；到点等待单独按设置计时。不会自动重发未确定结果的运动，也不会自动使能、重启电机或重置零点。

## 记录含义

每轮在 B 点等待结束后记录一次同帧反馈，含轮次、浏览器 UTC 采样时间、任务号、六关节角、base_link 下 tool0 XYZ/RPY、原始电机协议角、任务关节目标、到位容差和核验状态。

- `verification_error_joint_angles_deg`：后端任务最后一次到位核验保存的误差（目标 − 反馈）。
- `sampled_error_joint_angles_deg`：等待结束采样时，用任务目标减去当前关节反馈得到的误差。
- JSON 含 A/B 点位快照、速度/等待/次数、标定和模型编号、结束状态/中止原因，可在未完成时导出当前快照。
- CSV 每行一个目标点样本，数值最多三位小数，供表格软件与外部测量数据按轮次/时间对照。
- 页面 XYZ 极差 = 所有已记录解算位置各轴最大值 − 最小值，不是标准重复定位精度指标。坐标和关节反馈均依赖电机编码器、绳索模型与当前标定；绳索伸长、回差和真实末端误差需要外部量具测量。本功能尚不采集连续轨迹跟踪精度数据。

## 验证

`python3 scripts/test_web_repeat.py`：临时 HTTP 服务 + Playwright，全 WebSocket 拦截，不连接 ROS/CAN。覆盖 A/B 选择与标定门禁、两轮完整执行、精确任务匹配、等待计时、参数冻结和双重限速、导出、停止/任务失败/迟到应答、笛卡尔参数、反馈过期、全局停止、断连与移动端布局。

实机验收由操作者在网页发起：先用已核验的近距离 A/B、1 轮检查路径、到点等待和最终保持，再增加循环次数。此次开发未自动执行实机测试。
