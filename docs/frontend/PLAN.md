# 前端第二阶段计划

日期：2026-09-17。控制基线：`v0.1.0-stage1` / `756cac3`。
先形成并提交此计划，再实施首轮前端。实机保持停止，验证仅使用 mock 或合成反馈。

## 参考与设计判断

- [睿尔曼机械臂示教官方文档](https://develop.realman-robotics.com/robot/teachingPendant/armTeching/)：将关节示教、位置姿态、坐标系和状态组织为独立区域。
- [UR PolyScope X Move Tool 官方文档](https://www.universal-robots.com/manuals/EN/HTML/SW10_11/Content/prod-usr-man/software/PolyScopeX/polyx-introduction/polyx-Move-MoveTool.htm)：显式呈现参考坐标系、活动 TCP、平移与旋转。

借鉴操作分区和信息层级，使用 Pi Arm 自有视觉设计。当前只有 base_link/tool0，界面明确标识，
不提供未实现的坐标系选项。使用者/开发者是显示偏好，不是用户认证或后端权限。

## 首轮交付范围（本分支实施）

1. **工作台结构**：深色侧栏、浅色操作区、常驻连接/机器人状态/软件停止；适配桌面和平板。
2. **操作视图**：实时六关节概览、TCP 状态、预设姿态；单轴、多轴及输出轴目标按任务分区。
3. **状态透明**：真实/模拟/只读/方向测试模式明显区分；新鲜度、禁止运动原因、任务结果常驻。
4. **开发视图**：原始电机状态、坐标换算链、标定 ID、诊断 JSON、方向测试记录与事件日志。
5. **视觉规范**：中文排版、统一间距/按钮/单位、键盘焦点、足够触控尺寸、状态文字与颜色并用。
6. **代码维护**：HTML、CSS、控制 JS、展示 JS 分离，静态资源本地加载，不依赖 CDN 或前端构建工具。
7. **行为约束**：保留现有后端接口、DOM 测试标识、限速和请求门禁。切换视图不发送运动，
   不自动连接/使能/回零，不把软件停止命名为物理急停；陈旧数据不可显示为实时状态。

## 页面组织

- 顶部：连接地址、连接按钮、运行模式、软件停止。
- 侧栏：操作工作台、运行记录；开发视图额外显示诊断与方向测试入口。
- 工作台：状态概览 → 预设姿态 → 运动目标与参数。全局输出轴限速对所有运动类型可见。
- 右侧/下方：六轴反馈、末端姿态、任务状态和可操作原因。
- 开发诊断：原始电机、完整坐标链和导出；方向测试仍受 commissioning 后端许可约束。

## 验收

- 在 1440×1000、1024×768、390×844 检查布局，无页面水平溢出，表格允许局部滚动。
- 离线浏览器验证断线/过期/故障/只读状态、角色与导航、诊断导出，禁止发送真实 CAN。
- 使用完整 mock 链验证单轴/整臂/输出轴目标、打包/回零、停止和任务互斥。
- 通过网页在 mock 下验证笛卡尔 LIN，禁止助手执行实机笛卡尔运动。
- 截图检查实际渲染，记录验证结果；结束后停止 mock 和 HTTP 服务。

## 后续迭代（本轮不冒充已实现）

- 基于 URDF 的三维姿态预览与目标预览；需区分模型反馈和物理位置。
- 点位管理、示教程序与执行队列，先定义持久化与后端执行契约。
- 用户登录、权限控制、TLS 和操作审计，应由后端共同实现。
- 速度倍率实时调整、连续按住点动等功能需扩展控制协议与停止机制后实施。

## 实施顺序

计划提交 → 拆分静态资源 → 重构布局与状态展示 → 适配回归脚本 → 离线/完整 mock 验收 → 提交推送。
