# 到位精度与交互式控制开发计划

2026-09-17。存档：`v0.2.0-viewer-baseline` / `85974a2`，包含操作者已确认的实机只读三维显示。
分支：`feature/motion-accuracy-and-interactive-preview`。
实现与软件验收已完成，实机运动仍待操作者切换版本确认，见 [验收与操作说明](INTERACTIVE_REVIEW.md)。

## 顺序与提交

1. 修复所有运动的终点判定：每轴位置容差默认 0.2°、稳定 0.5 s、最多收敛 10 s；
   JTC 显式目标容差，manager 独立核验，停止后再次确认，网页显示目标与误差。单独测试、提交、推送。
2. 后端只读预览接口：输出轴反解、笛卡尔 IK、关节/笛卡尔规划与轨迹返回；复用正式模型和限位。
3. 前端交互：单关节滑块、拖动选中连杆改变关节目标、半透明预览、TCP 规划路径及轨迹回放。
   默认只预览；操作者可显式开启“松手执行”，每次手势至多下发一条有限目标，沿用任务互斥、限速与停止。
4. mock / 虚拟反馈验证、界面截图与使用文档；另一次 Git 提交。

## 边界

- 实机运动由用户在网页发起；助手不直接执行实机笛卡尔运动。
- 开发使用独立 build/install 和 ROS_DOMAIN_ID，实机服务保持原版本，最后由用户切换。
- 预览不使能、不获取运动写入许可、不发送轨迹执行请求。解算失败隐藏旧目标/旧路径并给出原因。
- 路径预览展示规划结果；执行前重新检查起点和请求参数，不能把任意浏览器轨迹直接当作已批准路径。
- 明确区分滑块/模型的关节目标拖动和相机旋转；失焦、取消手势、反馈过期、只读/忙状态不得意外下发。
- 真实误差无法在 mock 中证明消除。修复验证包含“反馈静止但位置未到”的失败场景，最终仍需现场回零复测。
