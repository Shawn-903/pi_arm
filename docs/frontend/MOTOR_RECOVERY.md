# 网页电机故障恢复

工作台新增「电机故障恢复」区，可选择 CAN 1–6，清除错误或重启选中的电机。
正常控制和方向测试模式提供恢复服务；只读监测仍禁止任何 CAN 写入。

## 操作与适用范围

1. 查看开发诊断中的原始电机错误码，先排除电源、温度、机械卡住等故障原因。
2. 停止运动，确认整臂静止并支撑可能在失能时下落的部分。
3. 先尝试「清除选中电机错误（0x9B）」。故障仍存在时，可点击「重启选中电机（0x07）」。
4. 等待恢复结果和新反馈。成功后选中的电机保持关闭，需操作者另行使能；不会自动恢复原轨迹。

FAULT、标定未通过或绳索反解失败，不再直接禁用恢复入口。后端使用原始电机反馈核验：
六轴反馈完整且新鲜、连续三帧静止、没有运动任务或方向测试，并确认停止应答。
真正断线、CAN 总线故障或无法收到原始反馈时不能依靠此按钮恢复，需要检查连接或现场断电重启。
欠压、过热等持续故障也不会因为发送重启命令就被认定为消除。

## 协议与实现

依据仓库 `docs/CAN总线通讯协议V2.6.pdf` 第 29 节（文件内封面标注 V2.36）：
重启帧为 CAN ID `0x140 + motor_id`、DLC 8、数据 `07 00 00 00 00 00 00 00`。
该命令没有应答，效果相当于重新上电；原有 `reset_motor` 是 `0x9B` 清错误，不能代替重启。

链路：`reboot_motor` WebSocket 请求 → `/pi_arm/reboot_motor` →
`/pi_arm/hardware/reboot_motor` → RealBackend → CanDriver。
方向测试直接使用 commissioning 管理服务。只允许一个明确的电机 ID，不提供一键全部重启。

发送前撤销运动写入许可、清除待发控制帧。重启只发一次、不自动重试；等待 500 ms 后发关闭命令，
再等待默认 1 s，要求角度及两类状态反馈都更新、错误清除、静止且已关闭。
成功结果表示「命令已发送且反馈恢复并确认关闭」，不是收到重启 ACK。
启动耗时更长或反馈不满足要求时返回失败，不放行运动。

重启可能改变 RAM 零点或多圈位置参考，本功能不写零点、不改标定。
重启前后按减速比换算的原始输出轴角差不得超过 0.2°。
出现跳变、超时或其他无法确认的情况，会在当前后端进程内锁定
`REBOOT_REFERENCE_UNVERIFIED`，保持运动禁止；再次清错或重启不会清除这项锁定。
需人工核验姿态与位置参考，必要时重新标定。
该锁定不跨进程持久化，**重启 ROS 服务不等于位置参考已修复**。
角度连续性检查也不能代替实际关节姿态核验。

网页显示服务可用性、恢复条件、请求进度及失败原因。请求处理中禁用再次恢复、使能和新运动；
软件停止保持可用。旧后端没有重启服务时按钮禁用并提示升级。

## 验证记录

- CAN 帧编码与模拟器测试：0x07 数据正确且无 ACK，不包含置零或位置运动。
- 管理门禁测试：允许 FAULT 下的原始静止反馈恢复；拒绝过期反馈、运行中和无效电机 ID。
- 网关测试：FAULT 下走管理服务，不发送运动 action；禁止 ID 0 和只读模式。
- 离线浏览器测试：故障恢复可点击，运动按钮禁用；忙碌、断线、过期、只读和旧后端受限；显示成功/失败结果。
- `scripts/test_web_recovery.py` 在独立 ROS 域的 mock 服务上验证浏览器到硬件管理服务的完整链路，
  重启只关闭选中电机、不产生运动任务。
- `scripts/test_reboot_vcan.py` 使用生产 RealBackend 和虚拟 vcan0 验证正常恢复、无反馈、角度跳变、
  故障持续、关闭命令无效五种场景。每次只发送一次选定电机的 0x07，不发 0xA4/0x88/0x19/0x95。

本次没有对实机发送重启或运动。实际启动耗时、重启后的零点保留行为仍需现场确认。
全仓回归共 205 项，203 项通过；两项既有预设速度测试固定断言 1°/s，
与工作区操作者修改的 3°/s 不符。本次保留该速度修改及第五轴方向修改，不将其混入恢复功能提交。

## 更新运行版本

停止旧程序后，在仓库根目录执行 `bash scripts/build.sh`，随后按主 README 启动正常控制或方向测试服务，
刷新网页。不要同时运行两套连接同一物理 CAN 的服务。
