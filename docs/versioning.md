# 版本管理

Pi Arm 用 Git 标签保存可恢复的代码版本，使用 `main` 和工作分支 `refactor/code-organization` 开发。其他设备和接续开发的 Codex 按本文件执行版本管理。

## 版本编号

- 当前版本为 `V0.54`，后续常规功能更新依次使用 `V0.55`、`V0.56` 等标签，统一使用大写 `V`。
- 较大的调整由项目负责人明确指定，再使用 `V0.6`、`V0.7` 等阶段版本。
- 一个版本可以包含多次提交。在一批开发更新完成、相关检查通过并合入 `main` 后，为该提交创建带说明的标签。
- 已发布标签保留其对应提交；后续修改通过新提交和新版本保存。

## 区分使用与开发

先按实际动作判断任务类型，再决定是否更新软件版本：

| 任务 | 版本处理 |
| --- | --- |
| 通过现有网页、命令或 Python 接口运行机械臂，执行标零、标定姿态采样、点位示教和实验 | 属于使用现有功能，沿用当前软件版本。零偏、点位、日志和实验数据按运行资料保存，并记录使用的标签或提交。 |
| 新增功能、修复代码缺陷、调整接口或运行行为、重构实现 | 属于开发更新，在工作分支提交，完成相关检查并合入 `main` 后发布下一版本。 |
| 单独整理文件、修正文档、补充使用记录 | 通过普通提交或资料归档保存，沿用当前软件版本；随功能更新修改的文档纳入该功能版本。 |

一次任务同时包含使用和开发时，分别记录实际运行结果与代码改动，按代码改动确定版本更新。测试按改动范围选择，遵循 [开发验证约定](../src/README.md#修改与提交约定)；本项目的相关运行测试在树莓派执行。

## 发布与跨设备查看

开发更新合入 `main` 前，在本文件补充版本记录，写明具体变化、相关验证结果，以及使用方式需要调整的地方。随后在 `main` 的该提交上创建带说明的标签，并将分支和标签推送到 `origin`。标签只包含该提交已经跟踪的文件，运行数据和仓库外的归档材料按对应版本另存。

其他设备在项目目录获取版本记录和标签：

```bash
git fetch origin --tags
git show origin/main:docs/versioning.md
git show --no-patch V0.54
```

需要运行某个历史版本时，按 [备份与恢复](../README.md#备份与恢复) 操作。

## 版本记录

### V0.54 · 2026-11-19

标零从已知关节角和当次编码器读数计算零偏。首次采集、重新采集和丢失文件后的重建都可独立完成。实机默认按接口加载一份零点文件，V0.52 和 V0.53 已保存的参考继续支持读取。操作与恢复见[软件标零](../src/pi_arm_tasks/pi_arm_tasks/zero_reference/README.md)。

树莓派虚拟 CAN 验证在隔离安装中移开了 R10 和旧零点文件，并改变了编码器读数。按同一关节姿态重建后，普通、只读和维护模式均恢复到该姿态。缺少零点时，普通模式保留原始反馈并禁止运动。

### V0.53 · 2026-11-19

软件标零将基础标定和本次采集结果保存在一份 YAML 中。实机控制、只读监测和网页维护会自动读取对应 CAN 接口的零点。首次采集使用包内 R10，旧格式的零点在下次成功采集时升级。操作步骤见[软件标零](../src/pi_arm_tasks/pi_arm_tasks/zero_reference/README.md)。

树莓派虚拟 CAN 验证覆盖机械零位、自定义参考姿态、重复采集、重启加载和写入失败。三个启动入口取得了相同的参考编号与关节反馈，网页仍能独立读取打包姿态。硬件单元测试验证了旧格式兼容及配置不匹配时的处理。

### V0.52 · 2026-11-17

重排网页为示教器布局：左侧功能导航，顶部连接、使能与停止，示教操作和三维模型并排。示教区分为逐轴步进、目标运动和拖拽示教；关节、位置、姿态步进显示当前反馈，每次点击执行一个增量。切换示教方式时取消旧手势并关闭松手执行。预设姿态与模型设置折叠收纳，电机恢复及完整坐标表归入开发诊断。

在线编程改为指令栏、步骤列表和参数区，可选择、排序、删除步骤及编辑循环内容；校验定位无效步骤并保留输入，运行快照单独显示。点位库与录入表并排，补充类型筛选和空结果提示，A/B 测试可展开；运行历史采用列表与详情并排。

树莓派上的前端验证覆盖三类步进请求与受理锁定、控制权/只读/反馈过期、程序编辑/暂停/停止、点位身份与完整精度导出、A/B 五轮模板、原有单次运动、预览竞争、故障诊断和拖拽入口。隔离 mock 中通过逐轴步进到位检查；桌面、小屏、200% 放大及滚动后停止按钮可见性通过检查。

请求编号兼容局域网 HTTP 页面，普通单次运动、步进和程序启动共用生成函数。本次更新为网页静态资源与相关说明，不改 ROS 接口、SDK、运动链或标定。刷新页面加载新版本资源即可；Python SDK 继续使用 0.51.0。使用方式见 [网页说明](../web/README.md)。实机停止响应和位置保持仍待接入电机后验收。

### V0.51 · 2026-11-17

新增树莓派执行服务和可独立安装的 Python SDK。网页、步骤程序与脚本共用独占控制权、到位核验和停止结果。支持有限步进、单层有限循环、步骤间暂停、等待暂停计时、即时停止、请求去重、断线/心跳处理和持久运行记录。A/B 重复测试改由树莓派执行，保留五轮试跑、采样字段与四个完整周期的统计口径。

网页补齐程序编排、点位搜索/详情/修改/导入导出与历史查询；运行快照和编辑目标独立显示，桌面、小屏及放大布局保留停止入口。点位名称与备注修改保留 ID，批量导入事务提交，导出保留完整精度。标定实现及已有标定资料未修改。

本版本从 `V0.5`（`d08330f`）开发。验证环境为树莓派 Ubuntu 24.04 / ROS 2 Jazzy、独立 mock 与合成 ROS 服务；Windows Python 3.13 和树莓派 Python 3.12 使用同一 `pi_arm_sdk-0.51.0-py3-none-any.whl`：

- 执行服务与网关共 232 项测试通过，覆盖停止竞争、暂停计时、请求去重、写盘失败、重启中断、点位事务和查询精度。
- ROS 到位与停止集成通过，含未持令牌请求拒绝、旧令牌失效、租约过期保持、取消、迟到响应与保持失败。
- 隔离 mock 中模拟执行服务崩溃：manager 在租约过期后保持，重启后旧程序标记为中断，没有派发下一步；新会话可正常创建。
- Windows 已安装 SDK 的 mock 验收通过：MoveJ、MoveL、直接运动、三类步进、阻塞/非阻塞、异常退出、心跳/断线、等待超时、A/B 冻结快照和 JSON/CSV 导出。树莓派独立环境完成安装和状态查询。
- 浏览器通过操作台、输入、预览竞争、原有单次运动、A/B 迁移、程序编辑/暂停/停止/记录、点位身份/导出与桌面/小屏/200% 布局检查。
- 正式工作区 11 个包统一重建完成；部署后的树莓派 SDK 通过直接运动、等待、原始参数与记录导出检查，既有运行资料的 SHA-256 核对一致。

升级需停止旧服务并统一重建 ROS 包，避免混用新旧 Action 类型。部署前备份现有点库和运行资料，默认 real/mock 记录分文件保存；既有点库首次修改另保留 `.v0.5.bak`。使用见 [执行服务](execution.md)、[网页](../web/README.md) 和 [Python SDK](../sdk/python/README.md)。

电机尚未连接，本次没有实机运动；停止响应时间与当前位置保持效果待接入电机后验收。
