# 版本管理

Pi Arm 用 Git 标签保存可恢复的代码版本，使用 `main` 和工作分支 `refactor/code-organization` 开发。其他设备和接续开发的 Codex 按本文件执行版本管理。

## 版本编号

- 当前版本为 `V0.5`，后续常规功能更新依次使用 `V0.51`、`V0.52` 等标签，统一使用大写 `V`。
- 较大的调整由项目负责人明确指定，再使用 `V0.6`、`V0.7` 等阶段版本。
- 一个版本可以包含多次提交。在一批开发更新完成、相关检查通过并合入 `main` 后，为该提交创建带说明的标签。
- 已发布标签保留其对应提交；后续修改通过新提交和新版本保存。

## 区分使用与开发

先按实际动作判断任务类型，再决定是否更新软件版本：

| 任务 | 版本处理 |
| --- | --- |
| 通过现有网页、命令或 Python 接口运行机械臂，执行标零、标定姿态采样、点位示教和实验 | 属于使用现有功能，沿用当前软件版本。零偏、点位、日志和实验数据按运行资料保存，并记录使用的标签或提交。 |
| 新增功能、修复代码缺陷、调整接口或运行行为、重构实现 | 属于开发更新，在工作分支提交，完成相关检查并合入 `main` 后发布下一版本。 |
| 单独整理文件、修正文档、补充使用记录 | 通过普通提交或资料归档保存，沿用当前软件版本；随功能更新修改的文档纳入该功能版本。 |

一次任务同时包含使用和开发时，分别记录实际运行结果与代码改动，按代码改动确定版本更新。测试按改动范围选择，遵循 [开发验证约定](../src/README.md#修改与提交约定)；本项目的相关运行测试在树莓派执行。

## 发布与跨设备查看

开发更新合入 `main` 前，在本文件补充版本记录，写明具体变化、相关验证结果，以及使用方式需要调整的地方。随后在 `main` 的该提交上创建带说明的标签，并将分支和标签推送到 `origin`。标签只包含该提交已经跟踪的文件，运行数据和仓库外的归档材料按对应版本另存。

其他设备在项目目录获取版本记录和标签：

```bash
git fetch origin --tags
git show origin/main:docs/versioning.md
git show --no-patch V0.5
```

需要运行某个历史版本时，按 [备份与恢复](../README.md#备份与恢复) 操作。
