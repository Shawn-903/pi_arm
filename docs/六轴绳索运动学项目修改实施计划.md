# 六轴绳索运动学项目修改实施计划

> 计划版本：1.0  
> 目标平台：Ubuntu 24.04、ROS 2 Jazzy  
> 适用项目：`pi-arm-main`  
> 当前阶段：新运动学代码和本地数学/静态验证已完成；等待 Ubuntu 24.04 / ROS 2 Jazzy 全量构建和实机标定  
> 当前数学基线：[绳索运动学模型说明（新模型）](./绳索运动学文档/绳索运动学模型说明_整理版.md)  
> 注意：本文主体记录上一轮实施过程，其中旧系数和旧半径仅用于历史追溯；当前运行值以数学基线和 `cable_kinematics.yaml` 为准。

## 1. 修改目标

将项目当前的“每个关节独立、一对一换算”传动实现，修改为符合真实机械结构的六轴整体绳索运动学，实现：

1. 六个 ROS 独立关节位置和速度到六个减速器输出轴位置和速度的整体映射；
2. 六个减速器输出轴反馈到六个 ROS 独立关节状态的整体反解；
3. 关节 2 对第三至第六自由度的绳长耦合补偿；
4. 第四、第五自由度的正弦弦长位置和速度模型；
5. 第六轴同轴双半径闭合绳路的一致性校验和无状态映射；
6. 绳索几何、CAN 协议坐标和 ROS 关节模型之间的清晰分层；
7. 独立、无 ROS API 依赖的 C++ 绳索运动学库和单元测试；
8. Mock、vcan 和真实机械臂的分阶段验证。

## 2. 已确认的需求基线

### 2.1 机构基线

- 机械臂最终为六个独立自由度；
- 真实电机数量为六个，CAN ID 为 1～6；
- 不得引入另一个七电机项目的映射；
- 每个电机驱动一对正反向绳索；
- 不存在两个电机共同驱动一个独立关节；
- 只有关节 2 会改变后续绳索回路的长度；
- 该绳长耦合不是附加关节角约束；
- 每个电机总成具有电机端和减速器输出端编码器，但机械臂没有独立关节编码器；
- 绳索运动学使用减速器输出轴角度，不直接使用电机转子角度；
- 暂不补偿绳索弹性、摩擦、回差和张力变化；
- 单向轴承只用于安装时手动张紧，不参与运行时计算。

### 2.2 电机、主动关节与机械同步关节

| 电机 ID | ROS 主动关节 | 同步关节 | 关系 |
|---:|---|---|---|
| 1 | `joint_01` | 无 | 第一自由度 |
| 2 | `joint_02` | 无 | 第二自由度 |
| 3 | `joint_03` | `joint_04` | `joint_04 = joint_03` |
| 4 | `joint_05` | `joint_08` | `joint_08 = -joint_05` |
| 5 | `joint_06` | `joint_07` | `joint_07 = joint_06` |
| 6 | `joint_09` | 无 | 第六自由度 |

现有三个 mimic 关系符合真实机械同步关系，必须保留。

### 2.3 绳索运动学基线

位置正向映射采用：

$$
\begin{aligned}
\phi_1 &= \alpha_1S_1 \\
\phi_2 &= \alpha_2S_2 \\
\phi_3 &= \alpha_3S_3+\kappa_3S_2 \\
\phi_4 &= \beta_4\sin S_4+\kappa_4S_2 \\
\phi_5 &= \beta_5\sin S_5+\kappa_5S_2 \\
\phi_6 &= \alpha_6S_6+\kappa_6S_2
\end{aligned}
$$

反向映射必须先计算 $S_2$：

$$
\begin{aligned}
S_1 &= \frac{\phi_1}{\alpha_1} \\
S_2 &= \frac{\phi_2}{\alpha_2} \\
S_3 &= \frac{\phi_3-\kappa_3S_2}{\alpha_3} \\
S_4 &= \arcsin\left(\frac{\phi_4-\kappa_4S_2}{\beta_4}\right) \\
S_5 &= \arcsin\left(\frac{\phi_5-\kappa_5S_2}{\beta_5}\right) \\
S_6 &= \frac{\phi_6-\kappa_6S_2}{\alpha_6}
\end{aligned}
$$

第六轴两条绳路必须满足：

$$
\frac{R_{6a}}{r_{6a}}
=
\frac{R_{6b}}{r_{6b}}
$$

$$
\frac{\sigma_{6a}R'_{2,6a}}{r_{6a}}
=
\frac{\sigma_{6b}R'_{2,6b}}{r_{6b}}
$$

第六轴不根据正反转切换半径，也不保存运动方向或上一周期的积分状态。

## 3. 当前代码与目标之间的差距

| 位置 | 当前实现 | 主要问题 | 目标 |
|---|---|---|---|
| `pi_arm_can/transmission.*` | 一个 `Transmission` 只处理一个关节和一个电机 | 无法表达 $S_2$ 对后续四轴的耦合 | 从 CAN 包中移除关节绳索模型 |
| `TransmissionConfig` | `reduction_ratio + cable_ratio + nonlinear` | 参数含义混合，且只有标量系数 | 分为绳索几何参数和执行器协议参数 |
| `RealBackend::write()` | 对六个关节逐个调用正向换算 | 只改变 $S_2$ 时不会补偿电机 3～6 | 先做六轴整体映射，再发送六个电机命令 |
| `RealBackend::read()` | 每个电机反馈独立反解为一个关节 | 无法从电机 2 与后续电机的组合反馈中消除耦合 | 先恢复六个输出轴角，再做整体反解 |
| 当前速度换算 | 非线性轴只使用固定倍数 | 未包含 $\cos S_i$，也没有 $S_2$ 速度耦合 | 使用当前位置相关的绳索雅可比 |
| `MockBackend` | 直接复制 ROS 关节命令 | 不经过真实传动路径 | 模拟输出轴或协议坐标，再通过反解生成关节状态 |
| `pi_arm.urdf.xacro` | 每关节配置 `cable_ratio` 和 `nonlinear` | 全局耦合无法由逐关节参数描述 | 保留执行器映射，几何参数改由全局 YAML 提供 |
| `vcan_motor_emulator.py` | A4/0x92 基本为协议回显；0x19 立即清零 | 清零语义与真实协议不一致 | 保持协议仿真，不内置绳索公式；修正 0x19 |
| 0x19 清零管理 | 发送后等待 0x92 立即变为零 | 真实设备需要重新上电，当前确认条件错误 | 确认 0x19 应答并提示重新上电 |

## 4. 目标软件分层

```mermaid
flowchart LR
    A["ROS 2 独立关节坐标<br/>S, Sdot"] --> B["pi_arm_transmission<br/>六轴绳索运动学"]
    B --> C["减速器输出轴坐标<br/>phi, phidot"]
    C --> D["pi_arm_hardware<br/>G、d 与单位换算"]
    D --> E["CAN 协议坐标<br/>a, adot"]
    E --> F["pi_arm_can<br/>SocketCAN 与协议帧"]
    F --> G["六个真实电机"]

    G --> F
    F --> E
    E --> D
    D --> C
    C --> B
    B --> A
```

各层职责：

### 4.1 `pi_arm_transmission`

负责：

- 六轴关节位置到输出轴位置；
- 输出轴位置到六轴关节位置；
- 六轴速度正向和反向映射；
- 绳索雅可比；
- 参数合法性和第六轴双绳路兼容性校验；
- 第六轴两条绳路残差计算；
- 加载绳索几何 YAML。

不负责：

- ROS 消息；
- `rclcpp`；
- `ros2_control`；
- CAN 帧；
- 电机 ID；
- SocketCAN；
- 电机协议减速比；
- URDF 关节限制。

### 4.2 `pi_arm_hardware`

负责：

- ROS 主动关节顺序；
- 电机 ID 对应关系；
- 输出轴坐标与 CAN 协议坐标的比例和方向；
- 调用绳索运动学库进行整体正解和反解；
- 将 CAN 反馈的有效性、新鲜度和错误状态映射到关节状态；
- 继续执行现有的 URDF 关节位置和速度限制；
- 管理整机清零等硬件操作。

### 4.3 `pi_arm_can`

只负责：

- SocketCAN 收发；
- LK-TECH 报文编码和解码；
- 电机状态缓存；
- 位置命令批量发送；
- 电机管理命令；
- CAN 通信状态机。

CAN 包不再知道 ROS 关节、绳轮半径、正弦弦长和关节 2 耦合。

### 4.4 “无 ROS C++ 库”与 ROS 兼容性的关系

`pi_arm_transmission` 可以放在 ROS 2 工作空间中并使用 `ament_cmake` 构建，但公共 API 只使用标准 C++ 类型。

这意味着：

- 它在 ROS 2 工程中可以被 `pi_arm_hardware` 正常链接；
- 它不需要订阅话题、发布消息或创建 ROS 节点；
- 单元测试不需要启动 ROS；
- 将来可以在标定工具、离线分析程序或其他非 ROS 程序中复用；
- `ament_cmake` 是构建和安装方式，不代表数学库必须依赖 ROS 消息。

## 5. 新建 `pi_arm_transmission` 包

### 5.1 推荐目录

```text
src/pi_arm_transmission/
├── CMakeLists.txt
├── package.xml
├── include/pi_arm_transmission/
│   ├── cable_kinematics.hpp
│   ├── cable_kinematics_config.hpp
│   ├── config_loader.hpp
│   └── result.hpp
├── src/
│   ├── cable_kinematics.cpp
│   └── config_loader.cpp
└── test/
    ├── test_parameters.cpp
    ├── test_position_mapping.cpp
    ├── test_velocity_mapping.cpp
    └── test_axis6_closure.cpp
```

### 5.2 公共数据类型

建议使用固定长度类型：

```cpp
using Vector6 = std::array<double, 6>;
using Matrix6 = std::array<std::array<double, 6>, 6>;
```

参数结构应按物理类型区分：

```cpp
struct LinearAxisParameters;
struct CoupledLinearAxisParameters;
struct CoupledChordAxisParameters;
struct Axis6BranchParameters;
struct CableKinematicsParameters;
```

不要继续使用一个 `cable_ratio` 同时表达多个不同机构。

### 5.3 建议公共接口

```cpp
class CableKinematics
{
public:
  explicit CableKinematics(CableKinematicsParameters parameters);

  KinematicsStatus joint_to_output_position(
    const Vector6 & joint_position,
    Vector6 & output_position) const noexcept;

  KinematicsStatus output_to_joint_position(
    const Vector6 & output_position,
    Vector6 & joint_position) const noexcept;

  KinematicsStatus joint_to_output_velocity(
    const Vector6 & joint_position,
    const Vector6 & joint_velocity,
    Vector6 & output_velocity) const noexcept;

  KinematicsStatus output_to_joint_velocity(
    const Vector6 & joint_position,
    const Vector6 & output_velocity,
    Vector6 & joint_velocity) const noexcept;

  KinematicsStatus jacobian(
    const Vector6 & joint_position,
    Matrix6 & jacobian) const noexcept;

  Axis6Residual axis6_residual(
    double joint2_position,
    double joint6_position,
    double output6_position) const noexcept;
};
```

设计原则：

- 参数加载和构造阶段可以抛出参数异常；
- 控制周期内的计算接口使用状态返回值，不依赖未捕获异常；
- 不进行动态扩容；
- 不保存上一周期方向；
- 不在库内进行 rad/deg 换算；
- 不在库内访问文件系统以外的 ROS 参数服务。

### 5.4 运行时错误类型

至少区分：

- 输入包含非有限数；
- 反正弦输入超出定义域；
- 第四或第五自由度接近速度反解奇异位置；
- 第六轴参数不兼容；
- 配置文件缺项；
- 参数半径非正数；
- 方向参数非法。

错误结果应带轴编号和关键数值，便于硬件插件给出明确日志。

## 6. 绳索参数 YAML

### 6.1 文件位置

建议新增：

```text
src/pi_arm_description/config/cable_kinematics.yaml
```

理由：

- 这些参数描述的是当前机械臂的物理几何；
- `pi_arm_transmission` 是通用算法，不应内置某一台机械臂的固定尺寸；
- `pi_arm_description` 已经是机械结构、URDF 和模型参数的归属包；
- 当前只考虑一台机械臂，因此暂不设计多机械臂命名空间。

`pi_arm_description/CMakeLists.txt` 需要安装 `config/` 目录。

### 6.2 YAML 内容边界

YAML 保存：

- $r_i$；
- $R_i$；
- $R'_{2,i}$；
- 轴模型类型；
- 耦合方向 $\sigma_i$；
- 第六轴两条绳路参数；
- 反正弦容差；
- 速度反解奇异阈值；
- 第六轴兼容性比较容差。

YAML 不保存：

- 电机 ID；
- CAN 接口名称；
- $G_i$；
- $d_i$；
- ROS 关节限制。

这些硬件接口信息继续由 `<ros2_control>` 配置提供，避免同一映射在 Xacro 和 YAML 中重复。

### 6.3 加载时的强校验

启动阶段必须验证：

- 文件存在且可读；
- 六个期望主动关节全部存在；
- 不允许未知或重复关节；
- 所有半径为有限正数；
- 所有耦合方向为 $-1$ 或 $+1$；
- 第四、第五自由度模型类型正确；
- 第六轴两条绳路的自身系数在容差内一致；
- 第六轴两条绳路的耦合系数在容差内一致；
- 小绳路和大绳路不能被解释为正反转状态。

配置失败时，硬件插件初始化必须失败，不能退回旧的一对一模型。

## 7. Xacro 与 ROS 2 模型修改

### 7.1 不修改的几何内容

以下内容全部保持不变：

- `link`；
- `visual`；
- `collision`；
- `origin`；
- `axis`；
- 关节名称；
- 关节上下限和速度限制；
- `joint_04`、`joint_07`、`joint_08` 的 mimic；
- MoveIt 运动链；
- 六个 ROS 主动关节。

原因是绳索耦合只影响“关节命令与电机输出轴之间的传动”，不会改变机器人关节几何和机械同步关系。

### 7.2 `<ros2_control>` 段的修改

在 Xacro 顶部增加参数：

```xml
<xacro:arg name="cable_kinematics_file" default="" />
```

在 `<hardware>` 中增加：

```xml
<param name="cable_kinematics_file">$(arg cable_kinematics_file)</param>
```

六个主动关节中保留：

- `motor_id`；
- `motor_direction`；
- 输出轴到协议角度的比例；
- position/velocity command interface；
- position/velocity state interface。

建议把含义模糊的：

```xml
<param name="reduction_ratio">...</param>
```

改名为：

```xml
<param name="protocol_angle_ratio">...</param>
```

删除：

```xml
<param name="cable_ratio">...</param>
<param name="nonlinear">...</param>
```

删除原因不是“Xacro 不再描述硬件”，而是：

- `motor_id`、$G_i$、$d_i$ 是每个执行器独立的硬件接口参数，适合保留；
- `cable_ratio` 和 `nonlinear` 无法描述 $S_2$ 对多个轴的全局耦合；
- 绳轮半径和耦合几何必须由一个完整的六轴参数文件统一加载。

### 7.3 Launch 修改

修改：

- `pi_arm_bringup/launch/bringup.launch.py`；
- `pi_arm_description/launch/display.launch.py`；
- 需要生成相同 `robot_description` 的 MoveIt launch。

Launch 应：

1. 使用 `FindPackageShare("pi_arm_description")` 定位安装后的 YAML；
2. 将绝对路径作为 `cable_kinematics_file:=...` 传给 Xacro；
3. 允许高级用户通过 launch 参数覆盖该文件；
4. 在默认文件不存在时启动失败并给出明确路径。

### 7.4 不需要修改的上层配置

以下内容不需要因绳索耦合而修改：

- `controllers.yaml` 中的六主动关节列表；
- `moveit_controllers.yaml`；
- MoveIt SRDF；
- MoveIt 运动学插件配置；
- WebSocket API；
- `pi_arm_manager` 的六关节控制接口。

## 8. 执行器协议坐标层

### 8.1 新配置类型

在 `pi_arm_hardware` 中用明确结构替代 `TransmissionConfig`：

```cpp
struct ActuatorConfig
{
  std::string joint_name;
  std::uint8_t motor_id;
  double protocol_angle_ratio;
  int motor_direction;
};
```

`BackendConfig` 包含：

- 固定顺序的六个 `ActuatorConfig`；
- 绳索运动学配置文件路径或已加载参数；
- URDF 关节位置和速度限制；
- 现有轮询、新鲜度和运动阈值参数。

### 8.2 坐标换算

输出轴到协议角度：

$$
a_i=C_{\mathrm{rad\to deg}}d_iG_i\phi_i
$$

协议角度到输出轴：

$$
\phi_i=
\frac{a_i}{C_{\mathrm{rad\to deg}}d_iG_i}
$$

建议将该换算实现为可独立测试的小型纯函数，而不是散落在 `RealBackend::read()` 和 `write()` 中。

### 8.3 名称澄清

在不影响协议行为的前提下，逐步将代码中的：

- `motor_angle_deg`；
- `max_motor_speed_dps`；

重命名为：

- `protocol_angle_deg`；
- `max_protocol_speed_dps`。

这可以避免把 CAN 协议角度误认为减速器输出轴角度 $\phi_i$。

## 9. `RealBackend::write()` 修改

### 9.1 目标数据流

```text
ROS 六关节命令
    ↓
URDF 位置、速度限制检查
    ↓
CableKinematics 六轴正向位置和速度映射
    ↓
六个减速器输出轴目标
    ↓
G、d 和 rad/deg 换算
    ↓
六个 A4 位置命令组成一个批次
```

### 9.2 具体步骤

1. 检查输入向量长度为六；
2. 检查位置、速度全部为有限数；
3. 保留现有 URDF 关节位置限制；
4. 保留现有 URDF 关节速度钳制；
5. 使用完整关节位置向量计算 $\boldsymbol\phi$；
6. 使用完整关节位置和速度向量计算 $\dot{\boldsymbol\phi}$；
7. 将每个 $\phi_i$ 和 $\dot\phi_i$ 转换为协议坐标；
8. 为六个电机生成 A4 命令；
9. 一次性提交完整批次。

### 9.3 必须具备的耦合行为

当只改变 $S_2$、其余 $S_3$～$S_6$ 保持不变时：

- 电机 2 的目标必须改变；
- 电机 3 的目标必须改变；
- 电机 4 的目标必须改变；
- 电机 5 的目标必须改变；
- 电机 6 的目标必须改变；
- 电机 1 的目标不得因该耦合改变。

### 9.4 A4 最大速度

不能继续按单个关节固定比例计算每个电机最大速度。

正常情况下：

$$
\dot{\boldsymbol\phi}
=
\boldsymbol J_{\mathrm{cable}}(\boldsymbol S)
\dot{\boldsymbol S}
$$

协议速度由 $\dot\phi_i$ 换算。

当上层只提供位置、对应速度接近零时，为避免生成协议不允许的零最大速度，可按当前位置和所有关节速度上限计算每个输出轴的保守速度包络：

$$
\dot\phi_{i,\max}
\leq
\sum_j
\left|
J_{ij}(\boldsymbol S)
\right|
\dot S_{j,\max}
$$

之后：

- 转换为协议速度；
- 取绝对值；
- 检查 A4 的 `uint16` 范围；
- 最小有效值为协议允许的非零值；
- 超出范围必须报告配置错误，不能发生整数回绕。

## 10. `RealBackend::read()` 修改

### 10.1 目标数据流

```text
六个 0x92 / 0x9C 反馈
    ↓
协议坐标到减速器输出轴坐标
    ↓
CableKinematics 六轴位置反解
    ↓
使用已恢复关节位置进行速度反解
    ↓
ROS 六关节状态
```

### 10.2 位置反解顺序

1. 读取六个协议角度；
2. 转换为六个输出轴角 $\boldsymbol\phi$；
3. 先由 $\phi_2$ 得到 $S_2$；
4. 再消除第三至第六自由度中的 $S_2$ 耦合项；
5. 检查第四、第五自由度的反正弦定义域；
6. 只有成功得到完整有效结果，才更新对应关节状态。

### 10.3 速度反解

1. 将六个协议速度转换为 $\dot{\boldsymbol\phi}$；
2. 使用本周期已经恢复的 $\boldsymbol S$；
3. 通过逆雅可比关系恢复 $\dot{\boldsymbol S}$；
4. 检查第四、第五自由度的余弦项；
5. `in_motion` 根据恢复后的关节速度计算，而不是直接使用电机协议速度。

### 10.4 新鲜度依赖

由于耦合存在，关节反馈依赖关系变为：

| ROS 关节状态 | 必需电机反馈 |
|---|---|
| $S_1$ | 电机 1 |
| $S_2$ | 电机 2 |
| $S_3$ | 电机 2、3 |
| $S_4$ | 电机 2、4 |
| $S_5$ | 电机 2、5 |
| $S_6$ | 电机 2、6 |

因此：

- 电机 2 角度过期时，第二至第六关节位置都不能标记为新鲜；
- 某个后续电机过期时，只使其对应关节和相关状态失效；
- 不得用零值代替缺失的 $S_2$ 继续反解；
- 可保留上一份有效状态用于显示，但必须把 `fresh` 标记为 `false`；
- 进入 CONTROL 模式前应确保建立完整、有效且新鲜的六电机状态基线。

### 10.5 状态与错误映射

电机使能、错误码和反馈年龄仍来自对应电机。对于依赖两个电机的耦合关节：

- `fresh` 取两个必需反馈的逻辑与；
- `ages_sec` 取必需反馈中的最大年龄；
- `has_error` 可取必需电机错误的逻辑或；
- 原始电机错误明细仍应保留在硬件状态或日志中，避免只看到聚合结果。

## 12. MockBackend 与 vcan

### 12.1 MockBackend

MockBackend 不应继续直接复制关节命令。

建议内部保存：

- 六个虚拟输出轴位置；
- 六个虚拟输出轴速度；
- 或六个虚拟 CAN 协议位置和速度。

写入时：

1. 关节命令经过真实 CableKinematics 正向映射；
2. 保存虚拟输出轴或协议状态。

读取时：

1. 虚拟状态经过反向映射；
2. 生成 ROS 关节状态。

注意：同一个正解和反解相互抵消可能掩盖共同错误，因此数学库单元测试必须使用独立计算的期望值，不能只依赖 Mock 往返测试。

### 12.2 vcan 电机模拟器

vcan 模拟器保持协议设备职责：

- A4 保存协议角度目标；
- 0x92 返回协议角度；
- 0x9C 返回协议速度和编码器状态；
- 不在模拟器内实现绳索运动学。

0x19 修改为：

- 返回对应命令应答；
- 不立即把当前角度清零；
- 可记录“重新上电后应用零位”的模拟状态，或在本阶段仅验证应答语义。

### 12.3 vcan 端到端用例

必须增加“只命令 $S_2$”用例，验证抓取到的 A4 命令中：

- CAN ID 2～6 的协议目标均按预期改变；
- CAN ID 1 不发生耦合变化；
- 再由 0x92 回读后能够恢复原始六关节状态。
