# 02 ROS2基础概念

# 1.ROS 2

ROS 2不是操作系统，而是一套用于构建机器人软件的通信框架和工具集合。

它主要解决：

- 不同程序之间如何交换数据；
- 不同功能如何拆分为独立模块；
- 如何启动一组机器人程序；
- 如何描述机械臂模型；
- 如何进行运动规划和硬件控制；
- 如何跨计算机传输机器人状态。

ROS 2系统可以理解为一个由很多节点组成的通信网络：

节点A发布数据→Topic / Service / Action→节点B接收并处理

这些节点之间的通信通过DDS（Data Distribution Service，数据分发服务）这个通信中间件实现。

# 2.工作区

工作区是存放、编译和安装一组 ROS 2包的目录。

典型结构：

```
~/pi_arm/
├── src/       # 项目源码
├── build/     # 编译中间文件
├── install/   # 编译后的程序、库和资源
├── log/       # 构建日志
├── scripts/   # 项目辅助脚本
└── docs/      # 项目文档
```

其中：

- `src` 是需要保存的源码；
- `build`、`install`、`log` 都可以重新生成；

## 构建工作区

```bash
cd ~/pi_arm

source /opt/ros/jazzy/setup.bash

colcon build --symlink-install
```

- 这里的 `source` 是 Linux Shell 里的一个命令，作用是：

> **在当前终端中执行指定脚本，并让脚本对环境变量的修改立即作用于当前终端。**
> 
- `colcon` 是工作区构建工具。它不是只编译一个文件，而是管理整个 ROS 2 工作区里的多个包。

#### 执行后大致经历以下过程

### 1. 搜索 ROS 2 包

`colcon` 扫描：

```
~/pi_arm/src/
```

通过每个包中的 `package.xml` 识别包，例如：

```
pi_arm_interfaces
pi_arm_transmission
pi_arm_can
pi_arm_hardware
pi_arm_description
pi_arm_moveit_config
pi_arm_bringup
```

可以提前查看：

```
colcon list
```

### 2. 分析包之间的依赖

比如：

```
pi_arm_interfaces
        ↓
pi_arm_manager
        ↓
pi_arm_websocket
```

或者：

```
pi_arm_transmission
        ↓
pi_arm_hardware
        ↓
pi_arm_bringup
```

`colcon` 会按照依赖顺序构建，不能随便颠倒。

### 3. 判断每个包使用什么构建方式

ROS 2 常见两类包：

#### C++ 包

`package.xml` 中一般有：

```
<build_type>ament_cmake</build_type>
```

通过：

```
CMakeLists.txt
```

完成配置、编译和安装。

#### Python 包

一般有：

```
<build_type>ament_python</build_type>
```

通过：

```
setup.py
setup.cfg
```

安装 Python 模块和可执行入口。

这个项目两类包都有。

### 4. 生成 `build/`

例如：

```
~/pi_arm/build/pi_arm_hardware/
~/pi_arm/build/pi_arm_transmission/
```

这里包含：

- CMake缓存；
- 中间目标文件；
- 编译过程文件；
- 测试配置；
- 临时生成代码。

这是中间构建目录，不是最后运行目录。

### 5. 生成 `install/`

例如：

```
~/pi_arm/install/pi_arm_hardware/
~/pi_arm/install/pi_arm_description/
~/pi_arm/install/pi_arm_moveit_config/
```

这里才是最终供 ROS 2 查找和运行的安装结果，包括：

- C++ 动态库；
- ROS 2 可执行程序；
- Python 模块；
- launch 文件；
- YAML配置；
- URDF/Xacro；
- STL模型；
- 消息接口；
- 环境加载脚本。

### 6. 生成 `log/`

这里保存构建日志：

```
~/pi_arm/log/latest_build/
```

如果构建失败，可以在这里查找详细错误。

- `-symlink-install` 是 colcon 的可选参数，不是每个 ROS项目都必须使用。

它的作用是：

> 对支持的 Python 文件、launch 文件和配置资源，尽量在 `install/` 中建立指向源码的符号链接，而不是简单复制一份。
> 

开发阶段这样比较方便。例如修改 Python 脚本后，有时不需要完整重新复制安装文件。

为了简化操作，在实际项目中往往会把这些指令写到一个build.sh文档中，把固定操作封装起来。

所以这两种方式基本等价：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
```

和：

```bash
bash scripts/build.sh
```

## 加载工作区

```bash
source /opt/ros/jazzy/setup.bash
source ~/pi_arm/install/setup.bash
```

第一行加载系统 ROS 2 Jazzy，第二行加载自己编译的 Pi Arm 包。

因为构建只是把文件生成到了：

```bash
~/pi_arm/install/
```

当前终端并不会自动知道这个目录。

```
ROS 2 Jazzy系统环境：underlay（底层环境）
             ↓
Pi Arm自定义工作区：overlay（覆盖工作区）
```

“overlay”这个名字还有一层含义：如果系统 ROS 2 和自己的工作区里存在同名包，当前工作区里的包通常拥有更高搜索优先级，可能覆盖系统包。

- 注：关于sh和bash
    
    `sh` 最早指 Bourne Shell，现在通常代表一种更基础、更通用的 POSIX Shell 接口。
    
    `bash` 是：
    
    ```
    Bourne Again SHell
    ```
    
    可以把它理解成 `sh` 的增强版本之一。
    
    Bash 支持很多 `sh` 没有的扩展语法，
    

# 3.ROS包（Package）

包是 ROS 2源码的基本组织单位。一个包通常负责一类明确功能。

例如：

```
pi_arm_description
pi_arm_hardware
pi_arm_transmission
pi_arm_manager
pi_arm_websocket
```

每个包通常包含：

```
package.xml
CMakeLists.txt 或 setup.py
src/
include/
launch/
config/
```

#### `package.xml`

用于描述：

- 包名；
- 版本；
- 维护者；
- 编译依赖；
- 运行依赖；
- 测试依赖；
- 构建类型。

例如：

```
<depend>pi_arm_transmission</depend>
```

表示当前包依赖 `pi_arm_transmission`。

#### `CMakeLists.txt`

C++包使用它描述：

- 编译哪些源文件；
- 生成哪些库或可执行程序；
- 链接哪些依赖；
- 安装哪些配置和资源；
- 注册哪些测试。

#### package相关指令

查看包

```
ros2 pkg list | grep pi_arm
```

查看包安装位置：

```
ros2 pkg prefix pi_arm_description
```

查看包内的可执行程序：

```
ros2 pkg executables pi_arm_websocket
```

# 4. 可执行程序、进程和节点

## 可执行程序

编译或安装在磁盘上的程序，例如：

```
pi_arm_websocket
pi_arm_manager_node
ros2_control_node
rviz2
```

查看：

```
ros2 pkg executables pi_arm_manager
```

## 进程

可执行程序运行后，操作系统创建进程。

查看：

```
ps aux | grep pi_arm
```

## 节点 Node

节点是 ROS 2通信图中的逻辑参与者。

一个节点可以：

- 发布 Topic；
- 订阅 Topic；
- 提供 Service；
- 调用 Service；
- 提供 Action；
- 调用 Action；
- 保存 Parameter。

一个进程不一定只有一个节点。某些程序内部可以创建多个 ROS 2节点。

### 查看运行节点

```
ros2 node list
```

查看节点的完整接口：

```
ros2 node info /pi_arm_manager
```

它会显示：

```
Subscribers
Publishers
Service Servers
Service Clients
Action Servers
Action Clients
```

# 5. ROS 2 启动程序

主要有两种方式。

### 启动单个程序

格式：

```
ros2 run 包名 可执行程序名
```

例如单独启动 WebSocket 节点：

```
ros2 run pi_arm_websocket pi_arm_websocket
```

这种方式通常只启动一个程序。

### 启动一组程序

格式：

```
ros2 launch 包名 launch文件 参数
```

例如：

```
ros2 launch pi_arm_bringup bringup.launch.py \
  hardware_type:=mock
```

# 6. ROS 2 通信机制

## ROS Graph

所有正在运行的节点及其通信关系构成 ROS Graph。

查看整个 ROS Graph 最直观的工具是：

```
rqt_graph
```

## Topic：持续数据流

Topic适合持续、异步、单向的数据流。

典型关系：

```
Publisher
   ↓
 Topic
   ↓
Subscriber
```

发布者不需要等待订阅者处理完成。

### 本项目中的Topic

| Topic | 类型 | 作用 |
| --- | --- | --- |
| `/joint_states` | `sensor_msgs/msg/JointState` | 六个主动关节状态 |
| `/tf` | `tf2_msgs/msg/TFMessage` | 动态坐标变换 |
| `/tf_static` | `tf2_msgs/msg/TFMessage` | 静态坐标变换 |
| `/robot_description` | `std_msgs/msg/String` | URDF机器人模型 |
| `/pi_arm/hardware_state` | `pi_arm_interfaces/msg/HardwareState` | 硬件层状态 |
| `/pi_arm/state` | `pi_arm_interfaces/msg/RobotState` | manager整理后的整机状态 |

### 查看Topic

```
ros2 topic list
```

同时显示类型：

```
ros2 topic list -t
```

查看某一Topic类型：

```
ros2 topic type /joint_states
```

查看一条数据：

```
ros2 topic echo /joint_states --once
```

查看频率：

```
ros2 topic hz /joint_states
```

查看通信双方：

```
ros2 topic info /joint_states -v
```

## Message：Topic中的数据结构

Topic不是随意发送字符串，而是发送指定类型的消息。

例如：

```
/joint_states
```

使用：

```
sensor_msgs/msg/JointState
```

查看消息定义：

```
ros2 interface show sensor_msgs/msg/JointState
```

典型内容：

```
header
string[] name
float64[] position
float64[] velocity
float64[] effort
```

本项目 `/joint_states` 中通常只有六个主动关节：

```
joint_01
joint_02
joint_03
joint_05
joint_06
joint_09
```

`joint_04`、`joint_07`、`joint_08` 是 mimic关节，不需要控制器单独发布命令。

标准消息无法表达所有机械臂状态，因此项目定义了自定义接口。

## Service：短时间请求与响应

Service适合：

- 请求立即执行；
- 等待一个明确响应；
- 操作通常持续时间较短；
- 不需要持续反馈进度。

结构：

```
Client发送Request
        ↓
Service Server处理
        ↓
返回Response
```

### 本项目中的Service

| Service | 类型 | 作用 |
| --- | --- | --- |
| `/pi_arm/enable_motor` | `ManageMotor` | 使能电机 |
| `/pi_arm/disable_motor` | `ManageMotor` | 关闭电机 |
| `/pi_arm/reset_motor` | `ManageMotor` | 清除错误 |
| `/pi_arm/set_zero` | `ManageMotor` | 写入零位 |
| `/pi_arm/stop_motion` | `StopMotion` | 停止运动 |

底层硬件还提供：

```
/pi_arm/hardware/enable_motor
/pi_arm/hardware/disable_motor
/pi_arm/hardware/reset_motor
/pi_arm/hardware/set_zero
```

manager对外提供上层接口，并负责状态检查和操作仲裁。

### 查看Service

```
ros2 service list
```

过滤项目接口：

```
ros2 service list | grep pi_arm
```

查看类型：

```
ros2 service type /pi_arm/enable_motor
```

查看接口定义：

```
ros2 interface show pi_arm_interfaces/srv/ManageMotor
```

定义中的 `---` 分隔请求和响应：

```
int32 motor_id
---
bool success
int32 code
string message
```

## Action：长时间任务

Action适合需要一定执行时间的任务，例如机械臂运动。

Action包含三部分：

```
Goal：要完成什么
Result：最终结果
Feedback：执行中的反馈
```

并支持：

- 接受或拒绝目标；
- 周期反馈；
- 查询状态；
- 取消任务；
- 返回最终结果。

### 本项目中的Action

| Action | 类型 | 作用 |
| --- | --- | --- |
| `/pi_arm/movej` | `MoveJ` | 六轴关节运动 |
| `/pi_arm/movejs` | `MoveJs` | 多点关节轨迹 |
| `/pi_arm/movel` | `MoveL` | 末端直线运动 |
| `/pi_arm/direct_move` | `DirectMove` | 直接受控目标 |
| `/joint_trajectory_controller/follow_joint_trajectory` | `FollowJointTrajectory` | 控制器轨迹执行 |

查看：

```
ros2 action list
```

显示类型：

```
ros2 action list -t
```

查看Action详情：

```
ros2 action info /pi_arm/movej
```

查看接口定义：

```
ros2 interface show pi_arm_interfaces/action/MoveJ
```

Action文件有两个 `---`：

```
Goal
---
Result
---
Feedback
```

## Parameter：节点运行参数

Parameter属于某个节点，用来配置节点运行行为。

例如 WebSocket节点定义：

```
host
port
state_push_interval_ms
max_size_bytes
request_timeout_sec
joint_names
```

查看节点参数：

```
ros2 param list /pi_arm_websocket
```

读取端口：

```
ros2 param get /pi_arm_websocket port
```
